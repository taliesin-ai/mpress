## Capture checkpoint

Additional regressions against `d0edb5f` prove that capturing `v1` deletes an existing valid snapshot named `v1.tmp`, follows external store/output/file links, and produces an unverifiable snapshot when an ordinary nested asset is named `mpress-version.json`. The authenticated SDK MCP capture test checks outside sentinel bytes: the old operation can write outside the project and only report an error when listing afterwards. The public replay compiles the original production file and requires exactly three package failures plus the MCP failure; run `python3 audit/lean-fast-2026-09-30/evidence/s07-capture/replay-before.py`.

Capture now loads rooted configuration, guards source/store paths, uses rooted copy and an exclusively allocated private workspace, and checksums each copied stream. Only the root snapshot manifest is reserved; nested assets with that name are indexed. The completed snapshot retains its previous 0755 directory mode. Force replacement moves the old snapshot into an owned backup before promotion. Copy/manifest/promotion errors preserve the old snapshot; failed rollback retains the old data at the backup path reported in the error. Normal successful promotion removes only its own backup. No predictable label-derived scratch directory is removed.

Capture and removal hold a stable advisory store lock through their operation. Existing lock files require read access and are never truncated or unlinked. The Windows implementation uses the existing x/sys dependency; its version and the dependency graph are unchanged. Native Linux checks include six simultaneous goroutines, four separate processes, force/non-force conflicts, stream failure, FIFO rejection, external links, read-only stores/lock files and injected old-move/promotion/rollback failures. The original subprocess fixture contained a nonportable filename; it was corrected to ordinary portable fixture names before qualification. Public full race and vet pass. Windows amd64 and macOS arm64 projectfs/version tests compile; native execution remains Linux only.

All 100 plain self-doc files and 199 mounted self-doc files are byte-identical. Capture/verify/list/force/remove work on the same complete corpus. All 2,165 full Wails strict ZIP entries remain identical. Five alternating before/after full Wails captures produce identical 2,165 files and manifest checksums. Peak RSS medians are 89,132 → 42,964 KiB, while elapsed medians are 1.03 → 1.43 seconds. This is a measured memory reduction with a runtime cost, **not a faster-capture claim**. Preserve this safety boundary when profiling the remaining cost. Source-pinned private qualification retains the same four failures and seven assertion messages; raw logs and fixtures remain private.

Ripwire records eleven major gating heuristics, reviewed without blanket acknowledgements: thin Root operation/atomic IO wrappers, necessary shared-IO churn and repeated sentinel fixtures. New capture and promotion complexity represents sequential resource acquisition and explicit failure/recovery branches; test entry points are reached by the Go runner. The detailed findings and review remain in `evidence/s07-capture/`.

## Required remaining work

- Mount still copies and rewrites with ambient IO. Reuse a pinned verified snapshot through copying, validate output destinations and retain navigation/base-path behavior. Close the remaining symlink policy checks in S04 alongside this work.
- List/Verify/Mount do not yet coordinate reads with force replacement/removal. Define coherent concurrent reads while preserving read-only snapshot stores. Locking currently covers capture/removal writers only.
- Ordinary process errors and rollback failures are covered. Automatic recovery after process termination/power loss between moving the old snapshot and promoting the replacement is not implemented; a hidden backup may require recovery. Native Windows/macOS locking/rename execution is unqualified. Nonshipping platforms outside the flock/Windows implementations report an unsupported-lock error.
- Profile the measured capture runtime cost on the pinned full corpus before changing IO for speed. Keep artifact/checksum equivalence and concurrency/failure cases as gates.
- Authoring translations/conversion, knowledge, deployment and metadata/watch operations still require the remaining S03 boundary work. Neither S03 nor S07 nor the final qualification gate is complete.
